## GazeScroll이란?

GazeScroll은 화면에 작은 플로팅 버튼을 띄웁니다. ▲ 또는 ▼ 버튼 위에 마우스 커서를 잠시 올려두면, 현재 사용 중인 앱이 자동으로 스크롤됩니다.

투명한 클릭스루 오버레이이므로 Chrome, 메모장, 터미널, 카카오톡 등 여러 Windows 앱 위에서 동작하면서도 화면을 가리거나 포커스를 빼앗지 않습니다.

마우스 휠도, 물리 클릭도 필요 없습니다.

## 누구를 위한 앱인가요?

- **마우스 휠·키보드·물리 마우스 조작이 어려운 분** — 안구 추적, 시선 마우스, 기타 접근성 입력 장치를 쓰는 분을 포함합니다. 포인터 이동만으로 스크롤하거나 키를 입력할 수 있습니다.
- **반복적으로 스크롤하는 분** — 문서, 웹사이트, 스크롤 가능한 콘텐츠를 오래 볼 때 반복 휠·클릭 동작을 줄이는 데 도움이 될 수 있습니다.

## 왜 단순한가요?

- **배울 것이 없습니다** — ▲와 ▼ 버튼만 보면 바로 무엇을 하는지 알 수 있습니다.
- **응시 진행 상태가 보입니다** — 커서를 올려둔 동안 게이지가 차오르므로 발동 시점을 예측할 수 있습니다.
- **꼭 필요한 설정만 담은 3개 탭** — 기능을 불필요하게 복잡하게 만들지 않았습니다.

GazeScroll은 복잡한 접근성 도구보다 가볍고 직접적인 사용 경험을 지향합니다.

## 주요 기능

- **커서만 올리면 스크롤** — 버튼 위에 설정한 시간만큼 커서를 두면 스크롤합니다. 물리 클릭은 필요 없습니다.
- **클릭 모드** — 즉시 동작을 선호하는 경우에 사용할 수 있습니다.
- **창 붙이기** — 버튼 그룹이 대상 창의 이동과 크기 변경을 따라갑니다. 8개 앵커 위치 중 하나를 선택할 수 있습니다.
- **붙일 창 허용 목록** — 선택한 앱에만 붙이거나, 목록을 비워 모든 창을 허용할 수 있습니다.
- **모양 사용자화** — 버튼 크기, 원형·둥근·각진 모양, 4가지 응시 게이지, 7가지 색상 팔레트, 테두리, 투명도를 설정합니다.
- **7개 UI 언어** — 한국어, English, 日本語, 简体中文, 繁體中文, हिन्दी, Español을 지원합니다.
- **작업을 방해하지 않음** — 트레이에 상주하고 항상 위에 표시되지만, 사용 중인 앱의 포커스나 포그라운드를 빼앗지 않습니다.

## 요구 사항

- Windows 11
- 휴대폰 원격제어 도구처럼 보호되었거나 관리자 권한으로 실행 중인 앱을 스크롤할 때는 관리자 권한이 필요할 수 있습니다.

## 설치

1. [Releases](https://github.com/ai-blink/GazeScroll/releases)에서 `GazeScroll-<버전>-win.zip`을 받습니다.
2. ZIP 파일의 압축을 풉니다.
3. `GazeScroll.exe`를 실행합니다.

설치는 필요 없습니다.

> 보호된 창 또는 관리자 권한 창을 스크롤하려면 GazeScroll도 관리자 권한으로 실행하세요. 자세한 내용은 [작동 원리](#작동-원리)를 참고하세요.

## 사용 방법

| 하고 싶은 일 | 방법 |
| --- | --- |
| **스크롤 또는 키 발동** | 버튼 위에 **700ms** 동안 커서를 올려두면 발동합니다. 계속 올려두면 반복 스크롤합니다. |
| **설정 열기 또는 버튼 이동** | **Alt+E**를 누르거나 화면의 **🔑 편집 버튼**에 3초간 응시합니다. **편집 완료**를 누르면 저장 후 일반 모드로 돌아갑니다. |
| **표시 또는 숨김** | **Alt+F12**를 누르거나 트레이 아이콘을 클릭합니다. |
| **종료** | 화면의 **⏻ 버튼**을 발동하거나, 트레이 아이콘을 우클릭한 뒤 종료를 선택합니다. |

설정에서 다음 동작을 바꿀 수 있습니다.

- **응시** 또는 **클릭**
- **단발** 또는 **반복**
- 스크롤 전달 방식과 응시 시간

설정은 아래 경로에 저장됩니다.

```text
%APPDATA%\gazescroll\gazescroll\settings.json
```

이 파일을 삭제하면 화면 중앙의 ▲·▼ 버튼 기본 레이아웃으로 초기화됩니다.

## 설정

편집 모드에서 세 개의 설정 탭을 사용할 수 있습니다.

- **동작** — 응시/클릭, 단발/반복, 스크롤 방식(`자동`, `크롬형`, `클래식`, `실제 휠`), 응시 시간.
- **모양** — UI 언어, 버튼 크기와 모양, 응시 게이지 방식, 색상 팔레트, 테두리, 투명도.
- **붙일 창** — 창 붙이기 켜기/끄기, 8방향 앵커 위치, 허용 창 목록 관리.

**✉ 문의** 버튼은 앱 정보, 제작자, 라이선스, 연락처를 담은 정보 창을 엽니다.

<summary><strong>작동 원리</strong></summary>

### 앱마다 스크롤 입력을 받는 방식이 다릅니다

전역 스크롤은 모든 앱에 같은 방식으로 전달되지 않습니다. GazeScroll은 대상 창 클래스를 기준으로 전달 방식을 선택합니다.

| 방식 | 적합한 대상 | 구현 |
| --- | --- | --- |
| **Post** | Chrome, Edge, Electron 앱 등 Chromium 계열 | 최상위 창에 `PostMessage(WM_MOUSEWHEEL)` 전송 |
| **Child** | 메모장, 터미널, 카카오톡 등 클래식 Win32 앱 | 가장 깊은 자식 컨트롤에 `WM_MOUSEWHEEL` 전송 |
| **Inject** | 메시지를 무시하는 앱, 휴대폰 원격제어 앱 | `SendInput`으로 실제 OS 휠 이벤트 전송 |
| **Auto**(기본) | 대부분의 앱 | `Chrome_WidgetWin*`에는 `Post`, 나머지에는 `Child` 사용 |

- Chromium 앱은 자식 컨트롤로 보낸 합성 휠 메시지는 무시하는 대신 최상위 창으로 보낸 메시지는 처리하는 경우가 많습니다.
- 클래식 Win32 앱은 가장 깊은 자식 컨트롤에서 스크롤 메시지를 처리하는 경우가 많습니다.
- `Inject`는 커서를 옮기지 않습니다. 오버레이가 클릭스루이므로 버튼이 대상 창 콘텐츠 위에 놓여 있어야 합니다. 창 붙이기가 이 위치를 자동으로 유지합니다.
- GazeScroll은 마지막 비-오버레이 포그라운드 창을 스크롤 대상으로 기억하며, 좌클릭 중에는 대상 창 갱신을 멈춥니다.

### 커서 올림 판정

오버레이는 휠 입력이 아래 앱으로 전달되도록 클릭스루 상태를 유지해야 합니다. 포커스를 받지 않는 Electron 창은 일반적인 마우스 이동 이벤트에 의존할 수 없으므로, GazeScroll은 50ms마다 전역 커서 위치를 읽어 hover/dwell을 판정합니다.

창은 `focusable: false`와 `showInactive()`를 사용하므로 포커스와 포그라운드를 빼앗지 않습니다.

### 프로젝트 구조

```text
src/
  main/index.ts             오버레이 창, 트레이, 전역 단축키, IPC, 커서·대상 창 폴링
  main/input.ts             koffi Win32 FFI: 스크롤, 키 입력, 커서 읽기, 창 열거
  main/settings.ts          설정 타입, 기본값, 불러오기, 저장
  preload/index.ts          contextBridge IPC API (window.api)
  renderer/src/main.ts      버튼 UI, 응시·클릭 판정, 붙이기, 설정 패널, 정보 모달
  renderer/src/style.css    버튼, 게이지, 패널, 시각 스타일
  shared/i18n.ts            main·renderer 공용 다국어 사전
```

renderer는 main 프로세스 모듈을 직접 import하지 않고 preload의 `window.api` IPC 브리지만 사용합니다. `input.ts`는 Electron 의존성이 없는 순수 Win32 FFI 코드입니다.

### 배포

```bash
npm run dist
# 출력: dist-release/GazeScroll-<버전>-win.zip
```

portable Windows 실행 파일은 요청한 권한 상승 수준을 안정적으로 포함하기 어려워 ZIP 타깃을 사용합니다. `koffi` 네이티브 바인딩은 ASAR에서 풀린 상태여야 합니다.

### 알려진 제약

- **Chromium 앱의 클릭 모드:** Chromium이 클릭을 처리하는 동안 합성 휠을 거부할 수 있어 클릭스루와 스크롤을 동시에 안정적으로 보장할 수 없습니다. 주력인 응시 모드는 정상 동작합니다.
- **관리자 권한 앱과 보호 표면:** Windows UIPI가 일반 권한 오버레이에서 보낸 입력을 차단할 수 있습니다. 필요한 경우 GazeScroll을 관리자 권한으로 실행하세요.

## GazeScroll とは？

GazeScroll は画面上に小さなフローティング操作ボタンを表示します。▲ または ▼ ボタンにマウスポインターを少しの間乗せると、使用中のアプリが自動でスクロールします。

透明なクリック透過オーバーレイなので、Chrome、メモ帳、ターミナル、KakaoTalk など多くの Windows アプリの上で動作し、画面を隠したりフォーカスを奪ったりしません。

マウスホイールも物理クリックも不要です。

## 誰のためのアプリですか？

- **マウスホイール、キーボード、物理マウスの操作が難しい方** — 視線入力、視線マウス、その他のアクセシビリティ入力デバイスを使う方を含みます。ポインターの移動だけでスクロールやキー入力の実行ができます。
- **作業中に繰り返しスクロールする方** — 文書、Web ページ、その他のスクロール可能なコンテンツを長時間見る際の、ホイール操作やクリックの繰り返しを減らせます。

## なぜ意図的にシンプルなのですか？

- **学習は不要です** — ▲ と ▼ ボタンを見れば、すぐに用途が分かります。
- **滞留時間のフィードバックが見えます** — ポインターを乗せている間に進行表示が埋まり、いつ動作するかが分かります。
- **必要な項目だけの 3 タブ設定パネル** — 不要な複雑さを加えません。

GazeScroll は、複雑なアクセシビリティツールよりも軽量で直接的な操作体験を目指しています。

## 主な機能

- **ホバーでスクロール** — 設定した滞留時間だけボタンの上にポインターを置くとスクロールします。物理クリックは不要です。
- **クリックモード** — 即時の操作を好む場合に使えます。
- **ウィンドウへの追従** — ボタングループは対象ウィンドウの移動・リサイズに追従します。8 つのアンカー位置から選べます。
- **対象ウィンドウ許可リスト** — 選択したアプリだけに追従させることも、リストを空にしてすべてのウィンドウを許可することもできます。
- **外観のカスタマイズ** — ボタンサイズ、円形・角丸・四角形、4 種類の滞留インジケーター、7 種類のカラーパレット、枠線、不透明度を設定できます。
- **7 種類の UI 言語** — 韓国語、英語、日本語、簡体字中国語、繁体字中国語、ヒンディー語、スペイン語に対応しています。
- **作業を妨げません** — システムトレイに常駐して最前面に表示されますが、使用中アプリのフォーカスや前面状態を奪いません。

## 動作要件

- Windows 11
- 一部のスマートフォン遠隔操作ツールなど、保護されたアプリや管理者権限で実行しているアプリをスクロールするには、管理者権限が必要になる場合があります。

## インストール

1. [Releases](https://github.com/ai-blink/GazeScroll/releases) から `GazeScroll-<version>-win.zip` をダウンロードします。
2. ZIP ファイルを展開します。
3. `GazeScroll.exe` を実行します。

インストールは不要です。

> 保護されたウィンドウまたは管理者権限のウィンドウをスクロールするには、GazeScroll も管理者として実行してください。詳しくは[動作の仕組み](#動作の仕組み)を参照してください。

## 使い方

| したいこと | 操作 |
| --- | --- |
| **スクロールまたはキーの実行** | ボタンの上に **700ms** ポインターを置くと実行されます。置き続けると繰り返しスクロールします。 |
| **設定を開く・ボタンを移動する** | **Alt+E** を押すか、画面上の **🔑 編集ボタン**に 3 秒間ポインターを置きます。**編集完了**を選ぶと保存され、通常モードに戻ります。 |
| **GazeScroll を表示・非表示にする** | **Alt+F12** を押すか、トレイアイコンをクリックします。 |
| **終了する** | 画面上の **⏻ ボタン**を実行するか、トレイアイコンを右クリックして終了を選びます。 |

設定では、次の項目を変更できます。

- **滞留**または**クリック**
- **単発**または**繰り返し**
- スクロールの送信方式と滞留時間

設定ファイルの保存先：

```text
%APPDATA%\gazescroll\gazescroll\settings.json
```

このファイルを削除すると、画面中央の ▲・▼ ボタンという初期レイアウトに戻ります。

## 設定

編集モードでは、3 つの設定タブを利用できます。

- **動作** — 滞留/クリック、単発/繰り返し、スクロール方式（`自動`、`Chrome 方式`、`クラシック`、`実ホイール`）、滞留時間。
- **外観** — UI 言語、ボタンのサイズと形、滞留インジケーターのスタイル、カラーパレット、枠線、不透明度。
- **追従するウィンドウ** — ウィンドウ追従のオン/オフ、8 方向アンカー位置、許可ウィンドウリストの管理。

**✉ お問い合わせ**ボタンを押すと、アプリ情報、作者、ライセンス、連絡先を含む情報ダイアログが開きます。

<details>
<summary><strong>動作の仕組み</strong></summary>

### アプリごとにスクロール入力の受け取り方が異なります

グローバルスクロールに万能な方法はありません。GazeScroll は対象ウィンドウのクラスに応じて送信方式を選びます。

| 方式 | 適した対象 | 実装 |
| --- | --- | --- |
| **Post** | Chrome、Edge、Electron アプリなどの Chromium 系 | トップレベルウィンドウへ `PostMessage(WM_MOUSEWHEEL)` を送信 |
| **Child** | メモ帳、ターミナル、KakaoTalk などの従来型 Win32 アプリ | 最も深い子コントロールへ `WM_MOUSEWHEEL` を送信 |
| **Inject** | 送信メッセージを無視するアプリ、スマートフォン遠隔操作アプリ | `SendInput` により実際の OS ホイールイベントを送信 |
| **Auto**（既定値） | 大半のアプリ | `Chrome_WidgetWin*` には `Post`、それ以外には `Child` を使用 |

- Chromium アプリは、子コントロールに送信した合成ホイールメッセージを無視する一方、トップレベルウィンドウへのメッセージは処理することが多くあります。
- 従来型 Win32 アプリでは、最も深い子コントロールがスクロールメッセージを処理することが多くあります。
- `Inject` はポインターを移動しません。オーバーレイはクリック透過のため、GazeScroll のボタンが対象ウィンドウのコンテンツ上にある必要があります。ウィンドウ追従機能がその位置を自動で保ちます。
- GazeScroll は最後に前面だった非オーバーレイウィンドウをスクロール対象として記憶し、左クリック中は対象の更新を停止します。

### ホバー判定

ホイール入力を下のアプリへ届けるため、オーバーレイはクリック透過のままである必要があります。フォーカスを受け取らない Electron ウィンドウは通常のマウス移動イベントに依存できないため、GazeScroll は 50ms ごとにグローバルポインター位置を読み取り、ホバーと滞留を判定します。

ウィンドウは `focusable: false` と `showInactive()` を使用するため、フォーカスや前面状態を奪いません。

### プロジェクト構成

```text
src/
  main/index.ts             オーバーレイ、トレイ、グローバルショートカット、IPC、ポインター・対象ウィンドウのポーリング
  main/input.ts             koffi Win32 FFI：スクロール、キー入力、ポインター読み取り、ウィンドウ列挙
  main/settings.ts          設定型、既定値、読み込み、保存
  preload/index.ts          contextBridge IPC API (window.api)
  renderer/src/main.ts      ボタン UI、滞留/クリック判定、追従、設定パネル、情報ダイアログ
  renderer/src/style.css    ボタン、ゲージ、パネル、視覚スタイル
  shared/i18n.ts            main と renderer で共有するローカライズ辞書
```

renderer は main プロセスのモジュールを直接 import せず、preload の `window.api` IPC ブリッジだけを通じて通信します。`input.ts` は Electron に依存しない純粋な Win32 FFI コードです。

### パッケージング

```bash
npm run dist
# 出力：dist-release/GazeScroll-<version>-win.zip
```

ポータブル Windows 実行ファイルでは要求された昇格レベルを確実に埋め込みにくいため、リリースは ZIP ターゲットを使います。ネイティブの `koffi` バインディングは ASAR の外に展開されている必要があります。

### 既知の制限

- **Chromium アプリでのクリックモード：** Chromium がクリックを処理している間、合成ホイール入力を拒否することがあるため、クリック透過とスクロールを同時に安定して保証できません。主要な滞留モードは正常に動作します。
- **管理者アプリと保護された画面：** Windows UIPI により、非管理者のオーバーレイからの入力がブロックされる場合があります。必要に応じて GazeScroll を管理者として実行してください。
